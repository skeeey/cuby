01APP ICON

这是唯一一个用户不打开 App 也会看到的素材：桌面快捷方式、开始菜单、任务栏、 Dock、访达、控制面板的「卸载程序」列表、安装包本身，全都读它。 现在这一整套还是 Memmy 的白毛球。

源文件
给我们一个 1024×1024 的源（SVG 更好），其余尺寸我们自己导出，不用你们逐个尺寸画。
16 px 可辨认
任务栏和文件夹列表里图标只有 16 px。现在的白毛球在这个尺寸下就是一团白。建议用屏幕脸的深色面板 + 天线小球做剪影，靠轮廓而不是靠颜色辨认。
两套底色都要能看
Windows 任务栏可能是深色也可能是浅色，macOS 菜单栏会随壁纸反转。图标本体的边缘和背景要有足够对比。
别带文字
应用图标里不要放「Cuby」字样——16 px 下读不出来，而且和 macOS 的圆角遮罩会打架。字标在下面第 07 节单独交。
菜单栏那张是硬要求。它必须是单色黑 + 透明通道的剪影，不能有渐变、不能用品牌蓝、不能有阴影。 macOS 只读取它的 alpha，然后按明暗主题整体反转成白或黑。任何彩色信息都会丢掉，只剩下糊在一起的形状。

04MCP

MCP 服务器卡片图标 已完成

「链接与工具 → MCP 服务器」里 Exa / Brave / Firecrawl / Figma 四张卡片的图标。 这里不是缺图，是取不到图——四个图标原本是同一行代码从 Google 的 favicon 服务实时拉的， 而 Google 在这个网络环境里不通，所以四张一起变空白。已改为随 App 打包，不需要额外提供图片。

当时的诊断。代码是 App/memmy-agent/src/entrypoints/frontend-bridge/mcp-presets-api.ts:65 的 favicon()，返回 https://www.google.com/s2/favicons?domain=…&sz=64， 四个预设共用。实测：该地址 8 秒超时（http 000）， 而 App 里另一处「消息渠道」图标用的 logos.composio.dev 0.33 秒返回 200—— 这正好解释了为什么只有 MCP 这一处是空的。

还有第二个问题：卡片组件的兜底图标只在 URL 为空时才显示 （mcp-tools-section.tsx:146-152），而这里的 URL 永远非空， 所以加载失败时既没有图也没有兜底，就是一个 48×48 的空白方块。

不需要设计
都是第三方商标，只有官方文件是对的，不要重画也不要改色。所以这一节不用你出图。
为什么选 LobeHub
它是唯一四个都齐的源。Composio 那个只有 Firecrawl/Figma/Exa 是真图，Brave 返回的是灰色占位网格； DuckDuckGo 和 Clearbit 在这里超时；Google 那套本来就不通。
加新预设时
补一张 SVG 进 assets/mcp-logos/、在 mcp-tools-section.tsx 的 mcpPresetLogos 里登记即可，不用改后端。没登记的预设会自动退回到通用服务器图标，不会再出现空白方块。

吉祥物本体已经交付了 14 个姿态（规格见 docs/brand/cuby-mascot-spec.html， 画布、锚点、比例都在那份文档里，这里不重复）。还剩 5 个预留姿态和 1 条待机动画。

欠件 · 沿用 cuby-mascot-spec.html 的画布与锚点
姿态画什么现在

「回退到 neutral」是当前行为：这 5 个姿态已经写进代码的类型里了 （App/frontend/desktop/src/components/mascot/cuby.tsx:49）， 调用方按名字引用，但找不到图就显示 neutral。所以现在不会报错，只是该有表情的地方一律面无表情。
待机动画
cuby-idle-alpha.webm —— 透明通道的循环动画，给桌面浮窗用。呼吸起伏 + 天线小球轻摆即可，2–4 秒无缝循环。这是清单里唯一一件动效。
画布
和已有 14 个姿态完全相同：512 px 宽、透明 PNG、高度自适应、共用同一锚点。不必重新讨论规格，照 cuby-mascot-spec.html 执行。
06CLI

命令行里的字符画

交互式命令行（cuby / cuby-memory）启动时会画一个用半块字符 ▀▄ 拼出来的角色。现在画的是已经退役的「米饭 + 勺子」。 

// App/memmy-agent/src/entrypoints/cli/tui.tsx:117
// "Half-block raster of the retired rice mascot, kept until the Cuby ASCII artwork lands."
const MASCOT_PALETTE = {
  rice0: "#FFFDF7",  rice1: "#F5EDE0",  rice2: "#DACDBD",
  spoon0: …, spoon1: …, spoon2: …   // ← 整套调色板都是米饭和勺子的颜色
}
要什么
Cuby 机器人头的半块字符画，大约 20 列 × 12 行。参考现有那张的密度——终端宽度紧张，不能再大。
颜色
同时给一份调色板（4–8 个十六进制值）和每个像素用哪个色的映射。现在是「米饭」6 色 + 「勺子」3 色，换成 Cuby 的蓝紫 + 天线橙即可。背景是深色的终端。
不是设计件
如果给不出字符画，给我们一张 Cuby 头部的小图（比如 256 px）也可以，我们自己做降采样。这条优先级最低。
