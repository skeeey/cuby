打包签名版桌面应用需要 Apple 与 Windows 生态的证书。本文说明两个平台的凭据要求、配置方式与打包流程。本地开发和 CI 冒烟构建使用未签名模式，不需要任何证书，见文末「未签名构建」。

> 仓库不会也不应该包含任何证书或私钥。`Mac软件打包/` 已在 `.gitignore` 中忽略，`.signing-local/` 也被 `.*` 规则忽略。

## macOS

签名入口：`scripts/package-mac.sh --sign signed`，由 `scripts/internal/mac/signed-arm64.sh` / `signed-x64.sh` 实现。

### 需要的凭据

| 凭据 | 用途 | 默认位置 | 覆盖变量 |
|---|---|---|---|
| Developer ID Application 证书（`.p12`，含私钥） | 签名 App 与 DMG | `Mac软件打包/证书.p12` | `CUBY_P12_FILE`、`CUBY_MAC_CERT_DIR` |
| `.p12` 密码 | 导入临时 keychain | `.signing-local/p12-password.txt` 或 `Mac软件打包/证书密码.txt` | `CUBY_P12_PASSWORD_FILE` |
| App Store Connect API Key（`.p8`） | 提交 Apple 公证 | `Mac软件打包/AuthKey_CUARD5SC47.p8` | `APPLE_API_KEY` |
| API Key ID | 公证认证 | `CUARD5SC47` | `APPLE_API_KEY_ID` |
| Issuer ID | 公证认证 | `5ed1f28c-0bb2-4369-89fe-d04023d48d45` | `APPLE_API_ISSUER` |
| 临时 keychain 密码 | `codesign` 访问证书 | 自动生成到 `.signing-local/keychain-password-<arch>.txt` | `CUBY_KEYCHAIN_PASSWORD_FILE`、`CSC_KEYCHAIN` |

前置条件：

- Apple Developer Program 会员。Developer ID 证书只对该计划开放。
- 证书类型必须是 **Developer ID Application**。分发格式是 DMG，因此不需要 Developer ID Installer（那是 `.pkg` 用的）。
- 公证需要 App Store Connect API Key 所属账号具备相应权限。

### 证书身份（identity）

脚本默认使用发布证书：

```text
Developer ID Application: XINYUE REN (S7NLXHGBJ2)
```

对应 `signed-arm64.sh:17-18` / `signed-x64.sh:17-18` 中的 `CSC_NAME`（electron-builder 签 App）与 `CODESIGN_IDENTITY`（签外层 DMG）。如果 `.p12` 是其他账号或团队签发的，两个变量必须一起覆盖，否则 electron-builder 找不到匹配证书：

```bash
export CSC_NAME="Developer ID Application: Your Name (TEAMID)"
export CODESIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)"
```

### 打包流程

1. 创建临时 keychain，导入 `.p12` 并授权 `codesign` 使用（`signed-arm64.sh:88-113`）。
2. electron-builder 用 `CSC_NAME` 签 App 本体，启用 hardened runtime 和 entitlements（`App/shell/desktop/electron-builder.yml`）。
3. 生成 DMG。
4. 用 `codesign` 签外层 DMG。
5. `xcrun notarytool submit --key ... --wait` 提交 Apple 公证。
6. `xcrun stapler staple` 把公证票据钉到 DMG。
7. `hdiutil verify`、`stapler validate`、`spctl` 验证 Gatekeeper 接受。

`electron-builder.yml` 中 `notarize: false`，公证由外层脚本在 DMG 生成后完成，不走 electron-builder 内置流程。

### 命令

```bash
bash scripts/package-mac.sh --version 1.2.3 --arch arm64 --edition cn --sign signed
bash scripts/package-mac.sh --version 1.2.3 --arch x64 --edition intl --sign signed
```

必须在 macOS 上执行（`codesign`、`notarytool`、`stapler` 均为 Apple 工具），构建机需要保持联网且不休眠。

### entitlements

签名构建使用两个 plist：

- `App/shell/desktop/build/entitlements.mac.plist`
- `App/shell/desktop/build/entitlements.mac.inherit.plist`

当前包含 JIT、unsigned executable memory、disable library validation、麦克风、Apple Events（Computer History 向浏览器查询隐私窗口）。如果新增功能涉及新的系统能力，需要同步更新这两个文件，否则 hardened runtime 下会静默失败。

## Windows

签名入口：`scripts/package-win.sh --sign signed` → `scripts/internal/win/signed-x64.sh` → `build-nsis.sh`。

### 需要的凭据

需要一个由公共 CA 签发的 Windows **Authenticode 代码签名证书**。`electron-builder.win.yml` 设置了 `forceCodeSigning: true`，缺少证书会直接构建失败。

两种提供方式：

**方式 A：PFX 文件**（证书私钥可导出）

```bash
export WIN_CSC_LINK=/absolute/path/to/windows-code-signing.pfx
export WIN_CSC_KEY_PASSWORD=...
# electron-builder 标准变量同样有效：
# export CSC_LINK=/absolute/path/to/windows-code-signing.pfx
# export CSC_KEY_PASSWORD=...
```

**方式 B：证书已在 Windows 证书存储中**（硬件 U 盾、SimplySign 等云签名服务，私钥不可导出）

```bash
export WIN_CSC_SHA1=<证书 SHA1 thumbprint>
# 或者按证书主题名匹配：
# export WIN_CSC_SUBJECT_NAME=<证书主题名>
# 可选，默认 http://timestamp.digicert.com
export WIN_CSC_TIMESTAMP_SERVER=http://timestamp.digicert.com
```

方式 B 下脚本会把 SHA1 或主题名、以及 RFC3161 时间戳服务器传给 electron-builder。

### 其他要求

- 签名哈希固定 SHA-256（`electron-builder.win.yml:72-74`）。
- 必须带时间戳，否则证书过期后已分发的安装包签名会失效。PFX 方式由 electron-builder 默认处理，证书存储方式由 `WIN_CSC_TIMESTAMP_SERVER` 指定。
- 依赖 Windows SDK 的 `signtool`，因此必须在 Windows 上构建（脚本通过 `cygpath` 兼容 Git Bash 路径）。
- `signAndEditExecutable: true` 会同时写入版本资源。

### 命令

```bash
WIN_CSC_LINK=/abs/path/code-signing.pfx \
WIN_CSC_KEY_PASSWORD=... \
bash scripts/package-win.sh --version 1.2.3 --arch x64 --edition cn --sign signed
```

### SmartScreen

- EV 证书通常立即获得 SmartScreen 信誉。
- OV 证书需要累积下载量后才会消除「未知发布者」提示。
- 未签名包在 Windows 上会触发明显的安全警告。

## 未签名构建

本地开发、CI 冒烟构建不需要证书：

```bash
bash scripts/package-mac.sh --version 1.2.3 --arch arm64 --edition cn --sign unsigned
bash scripts/package-win.sh --version 1.2.3 --arch x64 --edition cn --sign unsigned
```

- macOS：`electron-builder.unsigned.yml` 设置 `identity: null`、关闭 hardened runtime 和公证，产物仅用于本地测试，向外分发会被 Gatekeeper 拦截。
- Windows：`electron-builder.win.unsigned.yml` 设置 `signExecutable: false`，产物会带「未知发布者」警告。

## CI 中的签名

- `.github/workflows/build-desktop.yml` 始终使用 `--sign unsigned`，GitHub Actions 中不配置任何签名凭据。
- `.github/workflows/github-draft-release-v2.yml` 不构建安装包，而是从 OSS CDN 下载已经签名的 6 个安装包（Windows cn/intl + macOS arm64/x64 cn/intl），校验完整性后创建 Draft Release。
- 签名版安装包由仓库外的内部打包机产出并上传 OSS。因此 GitHub 仓库的 secrets 中不需要 Apple 或 Windows 签名证书。

## 凭据保管

- `Mac软件打包/`（证书、`.p8`、密码文件）已在 `.gitignore` 中忽略。
- `.signing-local/` 由 `.*` 规则忽略，存放自动生成的 keychain 密码。
- 不要把 `.p12`、`.p8`、密码写进仓库、issue 或日志。
- 临时 keychain 位于 `/private/tmp/memmy-build-<arch>.keychain-db`，每次打包会重建；多账号或共享构建机上建议用 `CSC_KEYCHAIN` 指向独立路径。

## 最小凭据清单

| 平台 | 必需 | 可选 |
|---|---|---|
| macOS | Apple Developer Program 会员；Developer ID Application `.p12` + 密码；App Store Connect API Key `.p8` + Key ID + Issuer ID | 自定义 `CSC_NAME` / `CODESIGN_IDENTITY` |
| Windows | 公共 CA 签发的 Authenticode 代码签名证书：PFX + 密码，或证书存储中的 SHA1 / 主题名 | 自定义时间戳服务器 |
