## What You Need

A macOS or Windows desktop environment.

## Quick Setup

Download and install the Cuby desktop app. On first launch it automatically:

1. Sets `CUBY_HOME` and `CUBY_CONFIG`.
2. Installs the bundled CLI and prepares Hooks, plugins, and companion Skills for authorized Agents.
3. Prepares `~/.cuby/config.yaml`, the workspace, and the Memory SQLite database.
4. Starts the Memory service and the Agent gateway.

On the welcome page:

- Choose the CubeRouter registration or sign-in line (when more than one is offered).
- If you have a CubeRouter account, enter your username and password and select **Log in**.
- If you don't have a CubeRouter account, switch to **Register** and create one.

Enter the main workbench and send your first message from the input box. `Enter` to send, `Shift + Enter` for a new line, and type `/` to open the slash command panel.

Open "Memory → Cross-Agent access" and scan conversation history from Cursor, Claude Code, Codex, OpenCode, OpenClaw, Hermes, DeepSeek Harness, WorkBuddy, Pi, and qwenwork into the memory store. First-run onboarding lets you scan only or also install the matching Hook, plugin, or Skill for detected Agents.

After connection, Hooks and plugins capture completed turns and inject relevant memory automatically; WorkBuddy, Pi, and qwenwork use the Skill for on-demand memory access. See [Agent Sources & Scanning](/docs/memory/sources) for details.

To connect an Agent outside the built-in list, open **Advanced → Add another Agent**. Select `kimi code`, `zcode`, `minimax code`, or `coder`, or enter another name; Cuby discovers its history location and format, installs the Skill, and completes the first import.

Open the "Tool connections" page:

- Messaging channels: Telegram, Discord, iMessage, WeChat, Feishu, DingTalk.

## Advanced: Environment Variables

| Variable | Purpose |
| --- | --- |
| `CUBY_HOME` | Cuby data home directory (default `~/.cuby`) |
| `CUBY_CONFIG` | Main config file path (default `~/.cuby/config.yaml`) |
| `CUBY_MEMORY_TOKEN` / `MEMORY_SERVICE_TOKEN` | Bearer token for the Memory HTTP service |

`${ENV_NAME}` references in the config file are resolved automatically, so you never hard-code API Keys in config.
